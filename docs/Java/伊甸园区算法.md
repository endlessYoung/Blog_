# 伊甸园区算法

## 分代假设

大多数对象活不长。JVM 按这个假设把堆分成年轻代和老年代：年轻代经常回收，老年代放那些活过很多轮的对象。

年轻代再分成三块：**伊甸园区**，以及两个幸存者区 **S0**、**S1**。新对象先放进伊甸园区。

:::note 命名
只回收年轻代的这次收集叫 Minor GC。伊甸园区空间不够时就会触发它。老年代怎么回收，见 [JVM 分区](/Java/JVM分区)。
:::

## 一次对象的去向

::::scrolly
:::step 01 · 分配
新对象先进伊甸园区。A 仍被引用，B 创建完就没有引用了。
:::
:::step 02 · Minor GC
伊甸园区放满后触发 Minor GC。回收器找出还有引用的对象，没有引用的对象被回收。
:::
:::step 03 · 复制到 S0
存活对象从伊甸园区复制到空着的幸存者区，年龄加 1。伊甸园区被清空。
:::
:::step 04 · 换到 S1
下一次 Minor GC，A 还活着，就从 S0 复制到 S1，年龄再加 1。S0 被清空。两个幸存者区轮流担任“空的那一个”。
:::
:::step 05 · 年龄增加
之后每次 Minor GC，A 都在 S0 和 S1 之间复制一次，年龄加一。中间这些次这里不再逐次展开。
:::
:::step 06 · 晋升
年龄达到 MaxTenuringThreshold（默认 15）后，A 被移到老年代。长期存活的对象不再参与年轻代的每次复制。
:::
::::

## 三个常用参数

- `-XX:NewRatio=3`：老年代与年轻代的比例是 3:1。
- `-XX:SurvivorRatio=8`：伊甸园区与每一个幸存者区的比例是 8:1，所以 Eden : S0 : S1 = 8 : 1 : 1。
- `-XX:MaxTenuringThreshold`：对象在幸存者区里要经历多少次 Minor GC 才晋升。默认 15。

:::note 复制
Minor GC 不是把对象“挪走”，而是复制到另一块空的区域，然后把原来的区域整块清空。所以两个幸存者区始终有一个是空的。
:::
